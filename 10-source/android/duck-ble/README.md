# Xduck BLE Android App

原生 Android 首版（Android 8.0+），仅使用 BLE，不申请互联网或 Wi-Fi 权限。

## 安装与使用

APK：`30-artifacts/android/Xduck-BLE-0.1.3-debug.apk`（相对工程根目录）。这是本地调试签名包，供样机联调；正式发布需要独立维护发布签名。

0.1.3 固定优先级为手柄 > 蓝牙 > 网页拖动 > 键盘。手柄接入时 App 显示蓝牙待命，停止发送运动；释放控制会撤销蓝牙控制权，但保留蓝牙连接。

0.1.2 每次连接先关闭再开启通知订阅，用 hello 往返验证回复通道后才进入 PIN 认证；认证及协议验证成功后才清零重试次数，避免认证超时无限重连。RSSI 读取失败不再导致整个连接断开。真机效果待复测。

0.1.1 修复系统配对弹窗触发 Activity 暂停时断开连接的问题：配对保护持续到通知订阅完成且 App 回到前台。首次连接/配对失败后须点击设备重试；已建立连接丢失配对时不自动发起新配对。可直接覆盖安装 0.1.0。

1. 先更新并验证配套机器人 `btd`，开启加密配对（新版默认开启）。旧 `btd` 没有 `ble.info` 等接口，App 会拒绝接管。
2. 将 APK 复制到 Android 手机，允许文件管理器安装该 APK。
3. 打开 App，授权“附近设备”；Android 8–11 还需定位权限和系统定位开关才能扫描 BLE。
4. 扫描并选择机器人，在系统提示中完成蓝牙配对，输入机器人 6 位 PIN。
5. 等待状态到达，在移动页点击“接管控制”。确认环境安全后初始化、开启策略。
6. 左摇杆控制前后/平移，右摇杆转向。任一摇杆松手或触摸取消会发送全零速度。
7. 离开 App、锁屏或失去连接后不恢复运动。回到 App 自动重连，仍须重新接管。

PIN 仅保留在当前进程内存中，不写磁盘。首次 PIN 从机器人既有标签或管理员处取得；管理员可在机器人使用 `robotctl system pin` 查看，不要把 PIN 放进日志或源码。

## 安全和功能边界

- 速度：10 Hz，直线最大 0.30 m/s，转向最大 1.0 rad/s；慢/标准/快三档分别限制至 0.10/0.20/0.30 m/s。
- 状态和 14 电机：2 Hz；运动估计来自 `odom.velocity`，不是将下发速度冒充实测速度。
- 状态超过 1 秒未更新就释放控制；机器人已有 500 ms deadman 独立于 App 执行。BLE 服务也撤销超时会话。
- 停车按钮是 BLE 零速度指令，不能替代物理急停。物理断线后手机无法再发送数据；机器人靠断线事件和 watchdog 停车。
- 每个控制租约使用新的随机标识，所有速度/动作共享递增序号和机器人单调时钟，超过 250 ms 的旧包被拒绝。
- 初始化、使能、放松及动作需确认。动作仅在机器人已安装对应策略/声音资源时可执行；拒绝理由显示在底部。
- 二进制状态中的缺失/越界值显示 `—`，不冒充 0。缺少电池读数时不估算电量。
- 原有网络、相机及其他守护进程不因安装本 App 改变。App 本身完全不依赖它们。

## 构建与验证

工程根目录执行：

```sh
./60-tools/test-android-wire.sh
./60-tools/build-android.sh
```

需要 JDK 17、Android SDK 35 / Build Tools 35.0.0、Gradle 8.11.1。脚本默认读取 `20-build/android/toolchain/`，也支持 `JAVA_HOME`、`ANDROID_HOME`、`GRADLE_BIN`。源码可在 Android Studio 中直接打开；构建输出固定在 `20-build/android/`。

没有 AndroidX/Compose 或第三方 BLE 依赖。Android 原生 GATT 串行操作，JSON 按 MTU 切片；速度只有一个待发送槽，停车优先，序号在真正出队时分配。二进制状态必须完整且顺序正确才呈现。

协议和联调记录见工程根目录 `00-docs/ble-app/PROTOCOL.md`、`00-docs/ble-app/ACCEPTANCE.md`。
