# Xduck 行走起步改进工程说明

日期：2026-10-09  
范围：真实 Stand→Walk 策略切换下的确定性起步、持续行走及停止后再起步。本文说明当前实现与实验结论，供后续开发和训练交接使用。

## 1. 目标与当前状态

解决的问题：速度指令激活行走策略后，机器人应能从站立姿态起步并持续行走，避免原地不动或起步后再次停住。

策略职责以实际系统为准：0速度由站立策略负责，速度指令大于0.05时执行行走策略。本轮验证覆盖正向指令0与0.3，以及从0渐增至0.3的启动过程。其他方向、纯转向及阈值附近的路由应沿用生产代码，本轮结果不覆盖这些场景。

当前保留上一轮完整BC候选 `xduck_startup_demo_bc_20261009/full/bc_step_300.pt`。本轮 `refine_600.pt` 仅作实验产物：已知条件有改善，但独立测试和实际切换循环存在退步，未晋级、未部署。尚未开始后续柔性适配。

## 2. 控制架构

```text
速度指令 / 现有模式调度
        │
        ├─ 站立模式 → Stand599
        └─ 行走模式 → Walk actor（确定性均值）
                             │
              现有策略消费者 D.Policy
              观测预处理、历史维护、动作后处理
                             │
                关节目标 / 物理单位转换
                             │
                         电机与仿真
```

关键接口：

| 项目 | 当前实现 |
|---|---|
| Walk观测 | 61维，保持既有观测语义和排列 |
| Walk动作 | 14维，沿用关节顺序与动作尺度 |
| Actor网络 | 61→512→256→128→14，隐藏层ELU |
| 归一化 | 继承源模型，训练期间冻结 |
| 推理 | 使用actor均值输出，ONNX执行 |
| 策略频率 | 50Hz，即20ms一次 |
| 本轮仿真 | 刚性模型，每策略周期20个1ms机械步 |
| 站立策略 | 既有Stand599，负责零速等待和停车 |

训练和评估使用现有消费者处理动作，保持跨模式历史与物理动作单位一致。评估中逐步核对仿真目标与消费者输出，容差3e-7。没有向部署actor新增真实速度观测。

## 3. 改进方法

本轮采用示范监督微调（BC），从上一轮改进候选继续训练。

### 3.1 捕获真实交接状态

先由站立策略运行5秒，在切换到Walk前保存状态，包括物理状态、随机化参数、传感器相关状态、电机状态及消费者历史。

同一条件下，不同待评模型从同一个交接状态恢复，首帧61维观测要求完全相同，以降低初始状态差异造成的比较偏差。

### 3.2 搜索并验证起步示范

针对训练参数中的失败起步条件，在源策略均值动作上施加短时修正：

- 5种既有矢状面动作模式；
- 幅度1或1.5；
- 持续0.5秒或1秒；
- 修正结束后恢复源策略均值，继续验证持续行走。

最终统一采用同一修正模式，得到7条通过重放的示范。资格判断包含有效支撑转换、前进速度、启动时间、首个落脚方向、躯干姿态、根高度及终止状态；具体实现见 `search_teachers.py`、`replay_teachers.py`。

短时修正用于生成训练标签，没有作为额外的起步控制器加入最终ONNX部署链路。

### 3.3 组成训练集

| 数据类别 | 帧数 | 监督目标 |
|---|---:|---|
| 合格示范的起步修正段 | 350 | 示范动作 |
| 修正后的后续状态 | 700 | 冻结源策略在这些状态的输出 |
| 成功起步与行走保留状态 | 22200 | 冻结源策略输出 |
| 合计 | 23250 | 全部为非零行走指令 |

保留集覆盖当前源策略的成功起步前段、后续步态及既有数据中的非零行走状态。旧数据只贡献状态，其保留目标由当前源策略重新计算，避免把旧策略动作作为当前保留目标。

### 3.4 训练配置

- 优化器：Adam，学习率1e-6。
- 每个批次分别抽取128帧起步、128帧后续、256帧保留状态。
- 损失：起步误差 + 0.5×后续误差 + 2×保留误差；各项按源动作分布标准差归一化。
- 梯度裁剪：1。
- 保存100、300、600次监督更新的检查点。
- 只训练actor MLP；观测归一化、动作分布参数及critic均冻结。

这里的600次是监督优化更新，不是600轮PPO。检查点保留源模型训练进度与历史信息，新增BC来源记录；移除旧PPO优化器状态，单独保存BC优化器状态。若后续恢复PPO，必须使用新的PPO优化器。

## 5. 本轮结果与模型取舍

下表的8秒与12秒成功数对源模型及600步模型均一致：

| 集合 | 源候选 | 本轮600步 |
|---|---:|---:|
| 已知回归330091 | 29/32 | 31/32 |
| 已知回归440091 | 24/32 | 26/32 |
| 选择集880091 | 27/32 | 28/32 |
| 最终测试990091 | 30/32 | 29/32 |

已知条件53→57/64，由新增5个成功、损失1个原成功组成。两批新参数合计57→57/64，尚无泛化提升证据。

真实循环为：Stand等待2秒→Walk行走6秒→Stand停车4秒→Walk再次行走8秒。

| 指标 | 源候选 | 本轮600步 |
|---|---:|---:|
| 第一次持续行走 | 16/16 | 15/16 |
| Stand停稳 | 16/16 | 16/16 |
| 第二次持续行走 | 16/16 | 14/16 |
| 两次行走均成功且中间停稳 | 16/16 | 14/16 |
| 环境终止 | 0 | 0 |

因此不替换源候选。拒绝晋级的原因是Walk激活后的行为退步；不以Walk自身的零速站立能力作为门槛。

这些结果来自有限批次仿真，不能解释为真实部署成功率，也未证明全方向、目标速度跟踪或柔性模型适应性。

## 6. 工程验证

已完成以下检查：

1. 同一交接条件下，各模型首帧观测逐元素相同。
2. 消费者动作与仿真物理目标逐步一致。
3. 非MLP actor字段及critic与源模型完全相同。
4. 训练数据零速样本数为0。
5. 512个真实观测上的PyTorch/ONNX最大绝对误差为3.34e-6。
6. 记录检查点、ONNX与数据集的SHA-256摘要。

单次起步测试中，本轮600步模型末2秒最大躯干倾角约8.92°，最低根高度约0.296m；这些是末段统计，不代表全轨迹极值。“没有终止”也不等于所有时刻姿态健康。

## 8. 后续改进建议

当前证据表明，短时起步监督能修复部分失败条件，但现有保留损失不足以阻止闭环行为退步。原因可能涉及监督误差分配或学生执行后的状态分布变化，尚未被单独对照验证。

下一轮建议：

1. 在训练参数中收集学生执行产生的状态，补充原成功起步附近的保留样本。
2. 比较更强的保留约束与更小的更新幅度，优先检查原成功条件是否保住。
3. 保留预先划定的候选选择集，新增未见参数作为最终测试。
4. 将真实Stand→Walk→Stand→Walk循环作为必要验收，逐条件记录收益与退步。
5. 在确认刚性模型的激活起步和持续行走改善后，再单独评估柔性适配及更广指令范围。

上述为下一阶段建议，尚未执行。当前可继续使用的候选仍为上一轮完整BC模型；本轮权重用于分析与后续实验。
